# Changelog

This project follows [Semantic Versioning](https://semver.org/).

## 0.1.0 - 2026-11-16

First release.

### Added

- TypeSpec authoring profile for public operations, named outcomes, nominal roles, provider defaults, and HTTP and IPC bindings.
- C#, Rust, and TypeScript generation of public types, validated construction, codecs, provider acceptance and dispatch, and HTTP and IPC consumers.
- Reference projections to JSON Schema, OpenAPI, and Markdown.
- Output publication that replaces the whole generated tree, refuses unowned or hand-edited output, restores the previous output when an earlier replacement was interrupted, and has a read-only drift check. Concurrent generators refuse ownership conflicts rather than racing output replacement or recovering an active publisher's backup; read-only checks do not acquire ownership, and abandoned ownership requires verified manual recovery.
- A real Linux Tauri/Wry webview acceptance fixture connects generated TypeScript consumers to generated Rust provider dispatch, including provider defaults, declared rejection, invalid wire input, state preservation, cancellation, and orderly shutdown.
- `@pattern` accepts only the safe common ECMAScript Unicode subset documented in the READMEs and specification. A pattern that Rust's engine could execute is still rejected when it lies outside that subset, even for Rust-only generation; Rust and C# retain their additional target restrictions. Unsupported source blocks all selected outputs rather than silently weakening validation.
- C# generation of `@pattern` for the safe common profile. Generated C# matches with a `RegexOptions.NonBacktracking` `Regex` over a translation that spells supplementary planes as surrogate pairs, and passes the same cross-language membership vector as TypeScript. The generator rejects, for C# only, a pattern whose estimated .NET automaton exceeds the engine's default limit of 10000 nodes (`^.{667}$`, for example), and the README states the estimate.
- Applications consuming pattern-bearing TypeScript modules declare the exact direct runtime dependency `"re2js": "2.10.0"`; the generator's transitive dependency is not sufficient. Pattern-free modules do not import it, and `@eslint-community/regexpp` 4.12.3 is generator-only.
- Generated TypeScript codecs use stack-safe synchronous construction, decoding, provider defaults, and encoding without a contract-level nesting limit. Exact numeric support comes from `lossless-json`; complete-document parsing additionally requires `@streamparser/json` 0.0.26.
- TypeScript construction, decoding, wire acceptance, and provider acceptance return `BoundaryRejection` with separate `violations` and `diagnostics` collections; failed inputs retain unknown-member observations without their values. Encoding and wire projection return a violation-array error type.
- JSON acceptance rejects duplicate object member names even when values match, leading BOMs at both text and byte entrypoints, invalid UTF-8, and unpaired UTF-16 surrogates. Embedded U+FEFF, well-formed characters, and exact numeric spellings remain unchanged.
- C# object and provider-accepted models are sealed get-only classes with reference equality; arrays are nominal immutable `<ArrayName>Codec.Value` wrappers with an invalid default state, constructed through the generated factories. Codecs, defaults, and composite value observations are stack-safe without a contract depth quota.
- C# provider-default dispatch uses exhaustive switch expressions. Default application reuses each completed shared child without merging distinct equal-valued children or unfolding a shared DAG into a tree; unchanged inputs keep their identity.
- Generated C# projects use exhaustive closed-type switches and ship `csharp/Contract.Analysis.props` and `csharp/Contract.EffectAnalysis.props`. A consumer writes the dependency paths and imports both once, in its repository's `Directory.Build.props`. The first imports the analysis props that TypeModeling owns, so omitted variants fail compilation without adding analyzer assemblies to runtime dependencies. The second imports the analysis props that EffectSystem owns and makes its usage diagnostics errors, including `EFFSYS014` and `EFFSYS015`, which reject a competing deadline timer or replacement of an incoming deadline at native consumer compilation.
- Generated C# projects declare no analyzer reference and import no props, so output outside the consumer's tree builds with `CS8509` warnings and is not analyzed unless a `Directory.Build.props` above it imports the same files.
- Rust IPC dispatch and transport exchange complete JSON `String` values and expose no parser DOM, so the original text passes through host and Tauri boundaries without being parsed first. Recursive values use immutable shared ownership with stack-safe codecs, defaults, equality, debugging, cloning, and destruction; the generated README specifies the separate declaration-derived compiler recursion allowance required in consumer crate roots.
- C# HTTP clients take an `IHttpTransport` as `IClientRequirements.Http`; use the generated `SocketsHttpTransport`, or implement the same no-redirect contract. Rust `ReqwestTransport::new` accepts a host-configured `reqwest::ClientBuilder` and returns `Result`. Both native adapters apply the no-redirect policy after host configuration, so a host-supplied configuration cannot re-enable redirects.
- Generated Rust manifests require 1.94.0, the pinned native acceptance compiler. The native Rust acceptance collection proves the exact minimum when run with `RUST_CONTRACT_EXACT_MINIMUM=1`, while general native builds allow newer compatible compilers.
- The emitter bundle keeps its declared runtime dependencies external, so it embeds no third-party code without its license notices. The generated TypeScript parser is a direct consumer dependency, not an emitter runtime dependency.
- Verification is split into fast commit acceptance (`verify`) and evidence-reusing native push acceptance (`verify:push`), with exhaustive test classification, Small and Medium tests run in network-, process-, and filesystem-restricted runners, a required-tool failure that fails the run rather than skipping a native test, and whole-tier resource ceilings.
- Native verification retains Nix host-target wrapper markers along with compiler and linker flags, so sanitized Medium runners resolve the same native libraries as the pinned development shell.
- Native C# preparation audits the dependency package graph online, checks NuGet's reported audited-project counts, and records exact package versions and archive hashes. Isolated per-fixture restores rely on that point-in-time audit only when every resolved package matches it; unavailable or incomplete audits, advisories, suppressed audit settings, and unaudited packages fail, so no restore depends on an expiring ambient HTTP cache. Release preparation refreshes the audit before acceptance.
- `npm run verify:summary` prints the recorded `verify:push` evidence for a release commit, so an annotated release tag carries the commit, toolchain, check results, and per-collection test and module counts.

### Security

- Generated TypeScript pattern checks and generator-owned default and finite-domain checks use synchronous RE2JS execution after exact, fail-closed subset translation, with no native authored-pattern matching or fallback. This removes catastrophic backtracking for a fixed admitted pattern, not unbounded total work across arbitrary input sizes or schemas. Before emitter preflight, TypeSpec 1.17.0's `@pattern` decorator still constructs native `RegExp(pattern)` for syntax checking without matching; frontend parsing and host resource budgets remain outside this guarantee.
- Same-value codepoint-length or UUID failures can skip that value's pattern check while retaining those violations and continuing independent fields. Pattern mismatches remain `format` violations; exhaustive same-value violations are not promised, and pattern validation uses the common boundary rejection type.
- Original pattern source remains in the internal model and schema projections. External validators own their execution safety; adopting this engine does not establish actual browser or Tauri integration verification.
- Generated C#, Rust and TypeScript keep contract descriptions, wire names, discriminator tags and string values as data: no line end or control character in a description or tag can leave its documentation comment or add code to the generated source, characters that XML or a comment cannot hold and the Unicode direction controls are spelled `\u{XXXX}` in documentation and escaped in literals, C# string literals escape NEL, LS and PS, Rust string literals keep text such as `\u0041` and the backspace and form-feed characters exactly, and the generated Rust crates run no doctests, so a fenced code block in a description is never compiled or executed.
  Rust HTTP placement structs use the same documentation escaping for encoded JSON member names.
- Generated HTTP clients in all three languages return a communication failure before sending when a path value is empty, `.` or `..`, or when a header value holds a control character other than a horizontal tab, and they never send a request outside the configured origin.
- Header checks in TypeScript precede `Headers` normalization, so leading LF and trailing CRLF cannot disappear before validation. All bundled HTTP transports refuse redirects, including same-origin redirects; generated clients classify 3xx and browser opaque redirects as contract defects.
- Route templates with an empty segment other than a trailing slash, a `.` or `..` segment in any percent-encoded spelling, a backslash, or a placeholder that does not fill a whole segment are rejected at generation.
